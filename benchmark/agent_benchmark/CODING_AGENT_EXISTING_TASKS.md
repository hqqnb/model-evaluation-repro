# 已有 Coding 与 Agent 题目筛选方案

日期：2026-08-03

## 1. 结论先行

本方案只评估已经实际测试过的题目，不从公开 Benchmark 重新选题。筛选标准不是“页面是否漂亮”或“是否像一个完整产品”，而是：

1. 题目是否能暴露模型在真实执行中犯的错误。
2. 失败是否能通过运行结果、最终状态或来源证据复核。
3. 题目是否主要测通用 Coding/Agent 能力，而不是前端审美或专业领域知识。
4. 不同模型的表现是否已经出现可解释的分化。

### 建议保留为候选的已有题目

**Coding**

- 2048 + Roguelike
- 小丑牌网页版
- 3D 数据可视化地球仪

**Agent**

- 当前没有适合直接进入 Agent 主分的已有题目。

Coding 六道正式候选题的完整题面和评分协议已经写入 `benchmark/CODING_TASKS.md`。这里的“保留”指保留为候选题，仍需按下文的能力归因和评分协议重跑；不代表原始测评结果可以直接作为正式分数。两道研究题只保留为研究专项候选。

### 建议降级为环境检查或体验辅助的题目

- 动态 SVG：长颈鹿驾驶微型汽车

它可以保留在测试流程中，用来确认模型是否能输出可运行的单文件产物、运行环境是否正常、预览链路是否可用，但不进入 Coding 主分。

### 建议不进入通用主分的题目

- iOS 18 风格四天气动态卡片
- 公司食堂约饭微信小程序
- FPV 穿越机模拟器
- 双叉臂悬挂运动学演示

其中前两道的主要问题是评分会被审美、页面完成度和交付物口径影响；后两道混入飞控、三维旋转、车辆工程和运动学等专业知识，不能稳定代表通用 Coding 智能。

## 2. 题目来源与判断依据

本次筛选依据是通过 InfoFlow CLI 读取的 KU 原始测评文档：

`https://ku.baidu-int.com/knowledge/HFVrC7hq1Q/MhgsouPC-w/NpaUpgpgHL/SN2WROxdiDTaio`

原始记录包含题面、各模型输出、预览结果和已有人工点评。记录中已经出现的有效区分信号包括：

- 功能表面完成但状态逻辑错误。
- 代码能够运行，但关键边界条件或规则没有实现。
- 模型交付了相邻但错误的产物，例如策划案、官网或 HTML 原型，而不是要求的小程序。
- 无法初始化、无法进入模拟或部分对象没有真正联动。
- 无法联网、使用过期价格、缺少来源或只覆盖单一地域。
- 任务整体看似完整，但事实与判断、来源与推测没有分开。

这些信号比“动效更细腻”“画风更接近原版”更适合进入正式测评。

## 3. 能力归因与结果评价

### 3.1 先区分“题目测到的能力”和“当前结果能证明的能力”

已有题目不是能力本身，而是观测某些能力的任务载体。一道题可能同时包含多个能力，但只有能够被独立验证、且不会被其他因素主导的部分，才适合进入主分。

现有 KU 记录主要是预览和人工点评，能够发现失败模式和形成题目筛选假设，但不能直接生成正式排名。原因包括：

- 没有统一的隐藏测试和固定输入。
- 部分题目的 Prompt 约束不足，不同模型交付物不完全可比。
- 部分评价把视觉效果、专业知识和功能正确性写在了一起。
- Agent 题目中的联网条件、资料时效和来源质量没有被单独控制。

因此，已有结果的正确用法是：**用来判断题目有没有区分潜力，用来提取失败模式；不能直接把原有人工排序当作 Coding 或 Agent 分数。**

### 3.3 Coding 题的结果如何评价

Coding 题不评价“页面像不像成品”，而评价模型交付的程序在规定输入下是否产生正确行为。每道候选题先设置一个**人类可读的黑箱检查面板**，再用同一组检查结果计算主分。

建议每道 Coding 题按以下结构评价：

- **核心行为正确性：50 分**：题目最重要的规则和正常路径是否正确。
- **状态、边界和异常：25 分**：重复操作、非法输入、失败、重开、空数据和资源失败是否正确处理。
- **交互或模块联动：15 分**：多个功能之间的数据和状态是否真正联动，而不是只做出展示层。
- **交付与兼容：10 分**：能否稳定启动、使用指定接口或在规定环境中运行。

人类审核者只看证据卡，不看模型解释。证据卡至少展示：

- 输入或操作序列。
- 预期结果。
- 实际结果。
- 一句自然语言差异说明。
- 该差异对应的分值。

具体到现有候选题：

- **2048**：展示操作序列、棋盘、得分、遗物和重开前后状态。不能把音乐、动效和主题创意计入主分。
- **小丑牌**：展示牌面、选牌、牌型、计分公式、资源变化和回合结算。不能把原版画风还原度计入主分。
- **地球仪**：展示指定城市、指标、时间点、点击返回值、航线信息和资源失败降级。不能把地球纹理、大气光晕和页面高级感计入主分。

旧 KU 结果最多用于判断“哪几个场景值得作为隐藏测试”，不能直接按原来的“综合表现排名”换算分数。

### 3.4 Agent 题的结果如何评价

Agent 题不评价计划写得是否漂亮，也不评价最终报告的文风，而评价模型是否完成目标、使用了正确证据并保持环境状态正确。

建议每道 Agent 题按以下结构评价：

- **目标完成：50 分**：最终交付物是否达到题目目标。
- **事实、数据和证据正确：25 分**：关键数字、对象、来源和引用是否对应。
- **约束、安全和不确定性处理：15 分**：是否遵守边界，是否标记冲突和未知信息，是否避免越权或擅自覆盖。
- **最终结果可使用：10 分**：普通审核者能否直接查看、复核和继续使用。

现有两道研究题不满足完整 Agent 主分的准入条件。它们可以继续用于研究专项，但如果未来改造成 Agent 题，必须增加：

- 起始环境状态，而不是直接给一个开放式研究问题。
- 至少两个可操作工具，并要求模型实际改变文件、任务、表格或消息等状态。
- 中间反馈会影响后续路径，而不是一次搜索后直接写报告。
- 至少一次工具失败、来源冲突或约束变化。
- 明确的终态检查，不以报告“看起来完整”作为完成标准。

旧 Agent 结果中“无法联网”只能说明模型在该次执行环境中没有完成联网任务，不能单独推出其研究能力弱；现有报告差异也不能直接推出 Agent 能力差异。

### 3.5 现有结果的正确使用方式

现阶段不应输出“某模型 Coding 得分多少”或“某模型 Agent 得分多少”。应先输出三类信息：

1. **能力假设**：这道题准备观察哪一种能力。
2. **失败证据**：模型具体在哪个输入、状态或来源上失败。
3. **评分准备度**：当前是否已经具备固定环境、机器判分和人类复核条件。

只有当第三项达到“可复核”时，题目结果才可以进入正式分数。否则只能作为探索性测评记录。

## 4. Coding 题目逐题判断

### 4.1 线程安全泛型有界阻塞队列

**结论：暂不采用，不进入当前正式题库。**

这道题的机器判分可以做得很客观，但主要证据是线程阻塞、唤醒、竞态和死锁等运行时行为。对于不具备编程基础的审核者，即使看到测试报告，也很难独立判断“测试是否覆盖了真正的问题”或“失败是否由模型代码导致”。这不符合本套题库的人工可审计要求。

因此不把它硬改成正式题，也不把它作为环境检查。后续如果建立可视化并发状态面板，能够直接展示生产者、消费者、队列容量、等待和唤醒过程，再考虑恢复。

### 4.2 2048 + Roguelike

**结论：保留，去除视觉主导，改成规则与状态机测试。**

已有记录中，模型在创意、动效和完成度上差异明显，但这些差异不能直接当作通用 Coding 分数。该题真正有价值的部分是：模型需要把 2048 的确定性规则和 Roguelike 的随机状态、遗物、死亡、重开组合成一个可玩的闭环。

**新版题目应固定的核心规则**

- 2048 的滑移、合并顺序和得分。
- 每次有效移动后的新方块生成。
- 遗物对规则的明确修改，例如改变生成概率、合并收益或一次性保护。
- 关卡或回合状态。
- 失败、死亡、重开和新局状态清理。
- 提供可注入随机种子，保证同一序列可复现。

**隐藏判分项**

- 固定棋盘输入的移动结果和得分。
- 连续相同方向移动不会重复合并。
- 遗物前后规则确实发生指定变化。
- 死亡判定准确，重开后旧分数、遗物和棋盘不会残留。
- 固定随机种子下结果一致。
- 重新开始、暂停或切换关卡不会破坏状态。
- 关键逻辑不能只写在点击事件中，必须能通过脚本调用或页面测试触发。

**人类复核方式**

提供“操作序列、预期棋盘、实际棋盘、预期分数、实际分数”的对照卡。页面试玩只作为辅助，不按音乐、画风和打击感评分。

### 4.3 小丑牌网页版

**结论：保留，主测卡牌规则和计分状态机。**

已有记录已经暴露出很有价值的错误：把一张牌识别为同花、没有牌型预测、出牌时出现 Bug。这说明题目能区分“看起来像游戏”和“真正实现规则”。

**新版题目应缩小为可验证的规则子集**

- 固定牌面和牌型定义。
- 至少包含高牌、对子、两对、三条、顺子、同花、葫芦、四条中的若干牌型。
- 出牌选择、牌型识别、基础计分。
- 资源状态，例如筹码、倍率或剩余出牌次数。
- 一张或两张会改变规则的 Joker。
- 回合结算、失败和重新开始。

不要求原版字体、音效、动画或像素级视觉还原。

**隐藏判分项**

- 牌型识别边界，尤其是同花、顺子和重复牌。
- 计分公式和倍率叠加顺序。
- Joker 对规则的实际影响，而非只显示说明。
- 选牌、取消选牌和重复出牌的状态一致性。
- 回合结束后资源正确扣减或增加。
- 失败和重开后没有继承上一局状态。

**人类复核方式**

证据卡展示牌面、选中的牌、识别出的牌型、计分明细和回合前后资源。这样可以直接感知“游戏是不是算对了”，而不需要理解前端代码。

### 4.4 3D 数据可视化地球仪

**结论：保留为综合 Coding 题，但视觉只作辅助证据。**

已有结果中，地球是否显示、城市标记是否漂移、控制面板和时间轴是否可用，已经产生了明显分化。问题不在于它是前端题，而在于原来的主评分把“逼真”和“美观”放得太重。

**新版题目应把可视化层变成可验证数据层**

- 使用固定的城市、国家和航线数据。
- GDP、人口、航班量等指标切换。
- 时间轴切换后数据随时间变化。
- 城市点击返回正确城市信息。
- 航线悬停返回正确航班信息。
- 经纬度到三维坐标的映射保持一致。
- 数据或纹理加载失败时，页面仍能显示降级状态。

**机器判分项**

- 指定城市是否存在且坐标误差在阈值内。
- 指定指标切换后显示值是否正确。
- 指定时间点的排序或聚合是否正确。
- 点击和悬停事件返回的对象 ID 是否正确。
- 视图交互不会修改原始数据。
- 资源加载失败时是否显示可识别的降级状态，而不是白屏。
- 构建、启动和基本交互是否稳定。

**人类复核方式**

审核者只需检查几个指定城市、指标和时间点，并观察点击弹窗、航线信息和失败降级。地球纹理、大气光晕和夜景效果不进入主分。

### 4.5 动态 SVG：长颈鹿驾驶微型小汽车

**结论：降级为不计分环境检查或体验辅助题。**

它能够检查单文件产物能否生成、XML/SVG 能否渲染、动画是否存在和预览链路是否可用，但主要差异来自图形细节、构图和动画审美。即使加入 XML 解析和渲染检查，也不足以覆盖通用 Coding 的代码理解、状态管理或工程维护能力。

**可保留的检查**

- 文件存在且是有效 SVG。
- 可在固定浏览器环境打开。
- 至少包含指定对象和动画节点。
- 没有明显渲染错误。

这些结果只用于排查环境和交付失败，不参与模型能力排名。

### 4.6 iOS 18 风格四天气动态卡片

**结论：删除出主分。**

已有结果主要按照质感、粒子、毛玻璃、动效和审美分化；即使能发现天气背景混杂、按钮在屏幕外、语言偏离 Prompt 等问题，主观视觉判断仍然会覆盖功能判断。它更适合作为产品原型体验题，而不是通用 Coding 题。

如果未来重新利用这道题，必须把它改成“状态切换组件”测试：四个状态互斥、状态切换不残留旧粒子、按钮可访问、状态数据正确；同时完全取消 iOS 还原和美观度要求。

### 4.7 公司食堂约饭微信小程序

**结论：当前版本删除出主分，不保留为正式 Coding 题。**

同一 Prompt 下，模型交付过微信小程序压缩包、HTML 原型、官网和产品策划案。这个结果本身能说明指令理解和交付物遵循存在差异，但不能在未固定运行环境的情况下公平比较代码质量。

如果未来重做，必须先固定：

- 统一交付为可在浏览器运行的本地应用，或统一交付为明确版本的微信小程序工程。
- 固定数据接口和本地存储方式。
- 固定必须完成的报名、匹配、取消、提醒状态转换。
- 用脚本检查报名人数、重复报名、跨部门约束和提醒状态。

在完成这些改造之前，不进入 Coding 主分。

### 4.8 FPV 穿越机模拟器

**结论：不进入通用 Coding 主分。**

它可以区分模型是否真正实现姿态、飞控、图传衰减和手柄输入，但题目同时要求航空控制、SO(3) 指数映射、PID 和三维模拟知识。模型失败时无法判断是编码能力不足，还是不熟悉飞控和数学模型。

它适合另立“科学与工程建模”专题，不适合当前通用 Coding 排名。

### 4.9 双叉臂悬挂运动学演示

**结论：不进入通用 Coding 主分。**

题目要求理解悬挂结构、约束几何、主销路径和车辆工程界面。已有结果中的“无法初始化”“只做成 2D”“车轮结构缺失”等现象有区分度，但错误归因不够干净。

它适合车辆工程或物理仿真专项测评，不进入通用 Coding 主分。

## 5. Agent 题目逐题判断

### 4.1 多模型 API 价格调研

**结论：不进入 Agent 主分，保留为研究专项候选。**

已有测试已经暴露出无法联网、模型名称或价格过期、缺少来源、没有区分输入/输出/缓存/长上下文档位等研究任务失败模式。但这些结果主要反映联网条件、信息时效和报告整理能力，没有充分体现模型是否能自主操作环境、根据反馈调整路径或处理工具失败。

**如果作为研究专项继续使用**

- 提供一组模拟官方价格页、版本公告、上下文说明和历史快照。
- 页面之间包含版本差异、长上下文价格、缓存价格和过期信息。
- 设置一个或两个来源冲突，要求模型保留冲突并说明处理方式。
- 禁止凭记忆补全未提供的价格。

**研究专项判分项**

- 指定模型是否全部覆盖。
- 输入、输出、缓存和长上下文价格是否填对。
- 价格单位和计费单位是否统一。
- 每个关键数字是否绑定到正确来源。
- 过期页面是否被识别，而不是直接覆盖最新信息。
- 性价比计算是否使用题目给定的调用量和质量指标。
- 未确认的信息是否明确标记，而非编造。

**人类复核方式**

审核者打开最终表格，随机抽查几个价格单元格即可看到来源、版本和计算过程；这能判断研究结果是否可靠，但不能据此判断完整 Agent 能力。

### 4.2 实时互动视频生成 / 世界模型学者研究

**结论：不进入 Agent 主分，保留为开放域研究专项候选。**

该题能检验多来源检索、对象筛选、证据归档和报告交付，但现有结果没有形成稳定的 Agent 区分度：差异主要来自联网能力、地域覆盖、引用完整度和写作质量。它没有要求模型把外部环境推进到一个具有副作用、可重放的终态，也没有充分测试工具失败后的重新规划。

**如果作为研究专项继续使用**

- 提供模拟搜索、机构主页、论文条目、项目页和个人主页。
- 来源包含时间、作者、机构、论文和项目之间的可交叉验证关系。
- 设置主题边界，排除机器人、自动驾驶和具身智能。
- 混入相关但不符合主题的候选人，以及信息不完整的候选人。
- 要求记录事实来源，不允许把搜索摘要直接当作论文事实。

**研究专项判分项**

- 是否选出规定数量的对象。
- 对象是否覆盖不同技术路线和地域，且满足主题边界。
- 每个代表论文是否真实对应对象，链接和标题是否一致。
- 论文解读是否使用论文中可验证的内容。
- 机构经历、主页和账号是否来自匹配来源。
- 事实与分析字段是否分开。
- 横向表格的字段是否完整、对象是否一致。
- 无法确认的信息是否显式标记为未确认。

**人类复核方式**

审核者先看候选人表格和来源链接，再抽查一到两个对象。该检查可以判断研究报告是否可靠，但不应转写为 Agent 主分。

## 6. 现有题目覆盖与缺口

### 已有题目可以覆盖的 Coding 方向

- 规则与状态机正确性：阻塞队列、2048、小丑牌。
- 交互式数据与多模块联动：3D 地球仪。
- 可运行交付和基本环境适配：动态 SVG可作为不计分检查。

### 现有题目可以覆盖的 Agent 方向

- 当前没有已有题目可以直接进入 Agent 主分。API 价格调研和世界模型学者研究只能覆盖“研究与信息整合”专项，不能替代 Agent 主分。

### Coding 仍缺少的方向

新增三道正式题已经补齐，分别覆盖：

1. **代码库理解与缺陷定位**：从失败现象、日志和跨文件调用关系定位隐蔽 Bug，并避免回归。
2. **跨文件功能实现或性能优化**：在已有项目架构中增加功能，要求接口、数据、边界和旧行为同时正确。
3. **可直接体验的确定性工具或应用**：结果状态普通人能看懂，核心行为又能用脚本检查，避免再次落入并发、审美或专业知识难以复核的问题。

新增题不以视觉展示为中心，也不要求模型掌握车辆、飞控等专业知识。新增题使用 Python，保留题使用 TypeScript；六道题均提供隐藏测试方向和自然语言证据卡。

### Agent 仍缺少的方向

需要重新设计六道正式题，覆盖以下方向：

1. **信息检索与证据整合**：在多个来源和冲突信息中找到正确事实，并将来源绑定到最终结果。
2. **多工具端到端执行**：在文件、日历、消息或任务之间完成一个普通人能理解的目标。
3. **多对象状态与约束管理**：同时处理时间、人数、唯一性、依赖和权限约束。
4. **动态重新规划与错误恢复**：执行中加入工具失败、资源变化或信息更新。
5. **结构化文档/表格交付**：把分散材料整理成可以直接使用并可核对的结果。
6. **长程 Agent 综合任务**：在多阶段、多工具和延迟反馈中保持目标、状态、约束和验证闭环。

其中长程题不额外加权；长程要体现为依赖链、状态跨度和反馈延迟，而不是单纯增加步骤数。

## 7. 统一改判原则

### Coding

- 机器测试决定主分，前端预览只作为人类理解证据。
- 模型自带的单元测试不能替代隐藏测试。
- 功能正确性、边界处理、回归兼容和性能约束必须分别展示。
- 不能把领域知识错误、视觉审美差异直接当作 Coding 失败。

### Agent

- 模拟环境提供稳定、可重置、可追溯的状态。
- 机器检查最终状态、来源绑定、约束遵循、重复操作和越权操作。
- 计划文本和写作风格不计主分。
- 真实联网能力可以单独记录，但不能把网络不可用与研究能力混成一个分数。
- 最终结果必须提供普通审核者可以直接浏览的证据视图。
