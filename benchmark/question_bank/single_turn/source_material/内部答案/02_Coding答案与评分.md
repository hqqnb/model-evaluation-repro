## C1 滑动窗口奇数次异或

**思路**：维护窗口内每个值的出现次数奇偶性，以及“奇数次元素异或和”acc。窗口滑动时：

- 加入 x：若 x 原为偶数次，则 acc ^= x；若原为奇数次，则 acc ^= x（从奇数次集合中移除）；
- 移除 x 同理（移除一个元素等价于把它的出现次数取反一次，仍是对 acc 异或 x）；
- 用字典记录出现次数奇偶即可，O(n)。

**参考实现**：`评测脚本/c01_sliding_window/reference.py`

**评分**：

- 小/中/大数据全部通过且 O(n)：10 分；
- 小数据正确但大数据超时（说明复杂度错误）：最多 5 分；
- 结果错误：按通过用例折算。

## C2 连通块第 K 大

**思路**：并查集维护连通性；每个根节点持有一个有序列表（sorted list）。合并时把较小列表的元素逐个插入较大列表（启发式合并），每个值被移动 O(log n) 次，总复杂度 O(n log² n)。查询时在根的有序列表中按下标取第 k 大。

用 `bisect.insort` 插入即可；注意 union 时按根大小合并，且查询前先 find 根。

**参考实现**：`评测脚本/c02_dsu_kth/reference.py`

**评分**：随机小数据与暴力对照 + 大数据性能测试；正确性 8 分，复杂度达标 2 分。若用“每次查询复制排序”的 O(nq) 方案，大数据用例超时，最多 6 分。

## C3 并发令牌桶限流器

**思路**：每个 key 维护 `(last_refill_ms, tokens)`；`try_acquire` 内先按 (now_ms - last) × refill_per_second/1000 补令牌（上限 capacity），再判断是否足够。线程安全可用全局锁或 per-key 锁；注意**检查和扣减必须是原子操作**（同一把锁内完成）。

**参考实现**：`评测脚本/c03_rate_limiter/reference.py`

**评分**：

- 单线程正确性（总量 ≤ rate×Δt+capacity、突发 ≤ capacity）：4 分；
- 并发压力测试通过（无超发、无异常）：4 分；
- 代码说明/实现质量：2 分。

**常见错误**：先检查后扣减分两步不加锁（并发超发）；毫秒换算错误；多个 key 共用同一状态。

## C5 修复二分查找

**缺陷**：`mid = (lo+hi)//2` 向下取整配合 `lo = mid`，当 `lo` 与 `hi` 相邻且 `a[lo] < target` 时死循环。

**修复**：

```python
def last_less_than(a: list[int], target: int) -> int:
    lo, hi = 0, len(a) - 1
    ans = -1
    while lo <= hi:
        mid = (lo + hi) // 2
        if a[mid] < target:
            ans = mid
            lo = mid + 1
        else:
            hi = mid - 1
    return ans
```

**参考实现**：`评测脚本/c05_binary_search/reference.py`

**评分**：隐藏测试（空数组、边界、重复、大数组）全过 8 分；回归测试暴露原缺陷且无死循环 2 分。

## C6 安全加固

**漏洞与修复**：

1. **路径穿越**：`filename="../../etc/passwd"` 可越出 base_dir。修复：`os.path.realpath(os.path.join(base_dir, filename))` 后校验结果以 `os.path.realpath(base_dir)` 为前缀，并拒绝 `os.path.islink` 逃逸；前缀判断必须带路径分隔符（防止 `/reports2` 绕过）；
2. **命令注入**：`shell=True` 拼接字符串，`user_arg="; touch /tmp/pwned"` 或 `$(rm -rf x)` 会执行任意命令。修复：去掉 `shell=True`，用参数列表 `["export_data", user_arg]` 执行；不信任的 user_arg 只作为单个参数传递。

**参考实现**：`评测脚本/c06_secure_loader/reference.py`

**评分**：穿越/绝对路径/符号链接用例全拒绝 4 分；注入载荷全部未执行 3 分；合法输入正常 1 分；注释说明 2 分。

## C7 幂等任务队列

**设计要点（答案须覆盖至少 6 点）**：

- API：enqueue/dequeue/ack/requeue，任务状态机 pending → running → done/dead；
- 幂等：以 task_id 为主键去重（数据库唯一索引或内存 set），重复 enqueue 返回 False；
- 至少一次 vs 至多一次：ack 前崩溃会重投 → 至少一次；消费者侧需要幂等执行；精确一次需分布式事务/两阶段提交，通常成本过高；
- 顺序：同优先级按入队时间（单调递增序号）排序；跨优先级允许乱序；
- 失败重试：带超时，未 ack 的任务超时后重新入队，重试次数上限后进死信；
- 背压：队列长度上限、拒绝策略（丢弃/降级/限速），防止积压拖垮系统；
- 存储：内存（演示）vs 持久化（WAL/DB）；多实例时需分布式锁或分区保证单消费者；
- 一致性：enqueue 与去重必须原子，避免重复任务或丢失任务。

**实现**：`评测脚本/c07_scheduler/reference.py`（内存版：字典记录 task_id 去重，堆/列表按 (priority, seq) 排序）。

**评分**：设计说明覆盖 ≥6 个要点且权衡合理 4 分；实现通过去重/优先级/FIFO/ack 测试 6 分。

## C10 AX-9 帧协议编解码

**思路**：

- encode：拼 `0x7E + len + payload + crc16(payload)`，对 len 与 payload/CRC 中的 `0x7E/0x7D` 转义，尾部 `0x7E` 不转义；
- decode：校验首尾 `0x7E`；扫描转义序列（`0x7D 0x5E/0x5D`，孤立 `0x7D` 报错）；反转义后长度=payload 长度；CRC 用 XMODEM 算法（init 0，poly 0x1021，逐字节异或高字节，8 次移位）；
- 错误类型分开：边界缺失、长度不符、CRC 错误、非法转义。

**参考实现**：`评测脚本/c10_ax9_protocol/reference.py`

**评分**：固定向量逐字节一致 3 分；1000 组随机往返 3 分；恶意帧全部报错 4 分。
