# 裸 API 测评运行协议

## 目标

这套协议的目标是让一次裸 API 测评尽量反映模型在指定 API 入口下的真实能力：

- 题目原样发送，不经过 Agent、工具调用、搜索、记忆或题目改写。
- 正确性测评优先拿到完整的最终响应，而不是优先拿到流式首字。
- 只有完整、非空、可评分的最终回答才计为成功。
- 一次逻辑请求无论发生多少次内部重试，结果文件中都只保留一行。

## 请求边界

每次请求由模型 ID、endpoint、题目原始 `messages`、模型参数和本次运行的
`delivery_mode` 共同确定。

Responses API 使用 `input` 字段，Chat Completions 使用 `messages` 字段。采集器不
额外插入系统提示词，不自动添加工具，不创建上下文记忆。

## 响应策略

默认遵循模型配置中的 `stream` 设置。当前正式配置中的 Opus 5 和 Opus 4.8
默认使用流式，其他模型默认使用完整模式；也可以用命令行 `--delivery-mode` 显式覆盖。完整模式请求
`stream: false`，等待一个完整 JSON 响应。
完整模式使用独立的 `ONEAPI_COMPLETE_TIMEOUT_SECONDS`，默认 600 秒；流式模式继续使用
`ONEAPI_TIMEOUT_SECONDS` 作为单次读取空闲超时，避免长推理在没有响应字节时被过早终止。

- Responses API 必须满足 `status: completed`，并且包含非空输出文本。
- Chat Completions 必须包含非空消息文本，并且终止原因不能是 `length`。
- HTTP 200 但状态未完成、输出为空或 JSON 不完整，都不算成功。

对于 Opus 5，`stream` 是当前模型配置下的默认正确性路径；其他模型可将它用于
延迟和推理片段专项测量。流式请求必须收到完整终止事件，并且仍然要求有非空最终
文本；收到一半就结束的回答不会被拼接后评分。

每个请求的内部 `metadata.json` 同时记录 `requested_parameters` 和
`effective_parameters`。前者来自本地实际发送的请求体，后者只来自上游响应回显；
如果两者不一致，应以 `effective_parameters` 作为“中转实际生效情况”的证据，
不能把本地请求参数直接当成供应商最终执行参数。

## 重复与交叉验证

正式测评默认对每个模型、每道题发起两次独立逻辑请求。两次请求使用相同的题目、
模型 ID、endpoint 和模型参数，但拥有不同的请求 ID、独立的网络调用和独立的原始
响应归档。采集器不会向题目或系统提示词中加入重复序号等额外标记。

两次结果都会保留在 `results.jsonl`，并分别保存在
`requests/<request-id>/` 下。需要单次运行时显式使用 `--repeat 1`，需要更多重复时
显式使用 `--repeat N`。这里的重复次数只指独立逻辑请求，不包含同一请求内部的
传输层 retry。

## 重试边界

默认最多尝试三次，可通过 `ONEAPI_MAX_ATTEMPTS` 或 `--max-attempts` 覆盖。
只对网络错误和超时、HTTP 429/5xx、SSE 解析错误、读取中断、未完成流，以及 HTTP
200 但 Responses 未完成或没有最终文本进行重试。

不对明确的请求错误、其他 4xx 或达到输出上限的回答重试。每次尝试的原始正文会
保存在请求目录中，最终选中的完整响应复制到约定的 `response.json` 或
`response.sse`。

对于 `convert_request_failed`、`not_implemented`、`unsupported_parameter` 或明确
包含 `not implemented` 的协议转换错误，不再按普通 5xx 重复重试，因为同一请求体
不会因重复发送而改变中转能力。

## 结果边界

正常结果展示不增加重试标签或诊断分类。每道题每次独立运行只有一条结果记录，
因此默认每道题有两条结果：

- 成功：只使用选中的完整最终回答。
- 失败：保留最终失败状态，不把半截回答当作成功。

内部 `metadata.json` 和 `error.json` 会保存尝试次数、失败原因和原始响应路径，用于
定位中转或网络问题，但这些信息不会增加 `results.jsonl` 的结果行。

## 刷新顺序

1. 先执行 `validate` 和 `preflight`。
2. 使用模型配置默认模式做低成本 smoke test；需要统一协议时显式传入
   `--delivery-mode complete` 或 `--delivery-mode stream`。
3. 确认请求体、最终回答和归档文件正常。
4. 再刷新正式题库；刷新时固定配置、题目文件和环境文件的哈希。
5. 历史运行只读保留，不用新协议覆盖旧结果。

## Claude 中转

Claude 没有官方 Anthropic Key 时，继续使用公司提供的 OneAPI 中转。该路径的结论
只能表示“指定中转入口下的模型表现”，不能把网页端或其他 Harness 的系统提示词、
上下文管理和工具增强效果归因给裸 API。协议本身会尽量排除本地传输层造成的假失败，
但上游中转的限流、协议转换或模型映射仍属于外部依赖。若响应回显的模型、温度、
工具或推理字段与请求不同，应以响应回显为实际生效证据，不能仅凭 `request.json`
认定参数已经生效。
